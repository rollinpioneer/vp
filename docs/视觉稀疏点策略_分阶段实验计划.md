# 可见性与任务上下文感知的稀疏点策略
## 分阶段实验计划 · 新仓库启动版

**工作名称：ViCo-Point（暂定，不代表已完成名称查重）**  
**版本：v1.0｜制定日期：2026-09-06｜状态：研究计划，尚未执行**

### 核心目标

在有限的视觉点预算下，让机械臂同时知道：**任务点在哪里、哪些位置当前可信，以及当前动作会受到哪些环境几何约束。**最终以遮挡和障碍条件下的实际任务成功率验证，而不只比较点预测误差。

### 总体路线

| 阶段 | 总体上做什么 | 主要输出 |
|---|---|---|
| V0 | 建立独立仓库，复现上游，冻结视觉输入与数据接口 | 可运行基线、复用清单、实验协议 |
| V1 | 分开验证遮挡和上下文缺失是否造成实际失败 | 四条件诊断、问题证据与难度设置 |
| V2 | 让任务点在遮挡期间具有明确的记忆和可信度 | 因果点记忆、可见性实验 |
| V3 | 在固定点预算下补入必要的环境约束点 | 静态上下文选择、碰撞与成功率结果 |
| V4 | 根据预测动作与不确定性分配上下文预算 | 完整方法、模块消融与效率结果 |
| V5 | 接入真实视觉提取，冻结方法并完成确认实验 | 多任务、留出布局和相机测试 |
| V6 | 有硬件时做实机验证，并固化论文证据 | 实机结果或仿真边界、发布材料 |

**执行原则：**每个阶段先做最小有效实验；能用简单方法解决的，不增加复杂模块。旧仓库只读，新方法不依赖 DataMIL、旧数据评分或旧 Top-20。

**范围：**主线为一类双指夹爪机械臂、刚性物体、固定相机、模仿学习；视觉为主要外部观测，机械臂本体状态允许辅助输入。暂不加入强化学习、大型世界模型、主动相机、人类视频迁移或失败恢复器。

# 1. 方法假设、上游依据与证据边界

### 1.1 本计划沿用的研究假设

**H1：可见性问题。**如果策略把遮挡时的旧点当成当前可靠观测，就可能做出错误动作；显式区分观测与估计，有望优于仅保持上一位置。

**H2：上下文问题。**任务物体点可能不足以描述障碍、边缘和通道；在相同点预算下保留动作相关上下文，有望优于只看任务点或随机背景点。

**H3：联合机制。**预测动作的空间范围与任务点不确定性可以指导上下文分配，使稀疏输入比固定几何裁剪更有效。H3 是待验证的主方法假设，不应因为模块增加就预设成立。

### 1.2 已核对的上游与本计划新增内容

Point Policy 使用语义关键点统一观察和动作，主要研究从人类视频学习机器人策略；Point Bridge 使用任务相关点表示组织跨域策略，并提供仿真、数据处理和策略训练接口。二者不能作为同一个算法互换名称。[1–3]

**主工程底座选择 Point Bridge。**本次读取的提交为 `5d567a62d62b5a97c5960d45024e065349680cda`。官方快速入门列出了 `bowl_on_plate`、`mug_on_plate`、`stack_bowls` 数据入口。其仿真实验区分真值点和视觉提取点，文档还提示仿真中的视觉分割并不总可靠。[3–5]

因此本计划会新增“相机可见点流”“持续任务点身份”“上下文点选择”适配层。它们**不是上游已经实现的功能**。Point Policy 是概念与后续外部基线；把 Point Bridge 缩减为少量任务点的版本，应命名为“同底座任务点基线”，不能称完整复现 Point Policy。

### 1.3 不夸大的最终主张

允许验证“遮挡鲁棒性、布局泛化和点预算效率”；不能提前声称完全消除遮挡、保证无碰撞、完整三维旋转不变或跨机器人泛化。

“固定点预算”仅约束进入策略的点/token 数。原始图像处理、深度估计、跟踪和候选点筛选仍有成本，必须计入端到端延迟。论文是否具有独立新颖性，V4 冻结前仍需针对点记忆和动作条件采样再次查新。

### 1.4 三种输入等级必须单独记录

| 输入等级 | 定义 | 可支持的结论 |
|---|---|---|
| O：全状态真值 | 含相机看不到的对象状态或完整模型点 | 复现与能力上界，不能证明抗遮挡 |
| P：可见深度＋仿真标签 | 仅使用相机当前可见表面，角色/身份可用仿真标签 | 表示机制验证，属于理想分割条件 |
| V：视觉提取 | 从 RGB-D 或双目及因果跟踪获得点、角色和置信度 | 真实视觉链路下的主要结果 |

机器人关节与夹爪传感器生成的本体点单独标记，不要求由相机检测。O、P、V 的结果不混在一张表里作为同条件比较。

# 2. 阶段 V0：新仓库、资产复用与可运行基线

**总体上要改进什么：**从旧数据估值工程中独立出来，建立一个能从相机观测训练和执行点策略的最小系统；先确保比较对象一致，不立即开发新模型。

## V0.1 创建新目录与上游连接

在实验机器建立与 `dm` 平级的 `vico-point` 目录，初始化独立 Git 仓库和独立 Python 环境。旧仓库保留只读路径 `LEGACY_ROOT`，不得在旧实验分支覆盖文件。

上游采用独立 `third_party/pointbridge` 子模块或固定提交副本；记录上游提交、子模块版本及许可证。Point Bridge 为 NVIDIA Source Code License，不可在复制时去掉原许可或将全部上游代码重新声明为自己的 MIT 项目。[3]

先直接运行官方支持的一项任务；保留上游入口、动作表示与控制周期。项目新增代码统一放在 `src/vico_point` 和 `experiments/v0` 等目录，不通过全仓库重构来“整理环境”。

**输出：**`upstream_lock.yaml`、环境文件、`asset_reuse.csv`、一次完整训练—评测记录。

## V0.2 一次性判断旧资产能否复用

优先复用固定随机场景、成功率汇总和数据索引的设计。旧文件只能“定点移植并验证”，不能因为过去运行过就自动判为正确。

旧 200 条轨迹只有在保留足够的模拟器状态、场景模型、相机配置和时间信息时，才可能准确回放并重渲染。**39 维状态观察不等于完整模拟器状态**；若缺少这些信息，旧轨迹不作为新视觉训练数据。最多用两条轨迹验证复用可行性，半个工作日仍不具备条件就改用上游数据。

旧 MetaWorld 仅作为可选的快速场景工具，不与主平台并行维护。旧 U0 工作可以单独完成，但不作为新视觉项目启动的前置条件。

## V0.3 复现上游的正常工作条件

优先任务：`bowl_on_plate`。先做一轮开发运行；模型按上游默认训练预算跑通后，用 20 个固定场景检查动作接口，再用 50 个验证场景确定正常成功水平。

上游建议的训练步数只能作为起点，不能据其特定硬件时间估算本机耗时。记录实际吞吐、显存和评测频率，不继承旧 DataMIL 的“4000 次更新”或 CPU-JAX 训练参数。[4–5]

复现输出包括：原始观测、模型输入点、动作解码、控制器接收动作和成功标记的一段对齐记录。只检查这条闭环所需的接口，不执行大范围测试。

**完成标准：**策略在正常场景能够学习并执行；任务点误差和控制命令不存在明显错位。如果正常条件接近全失败，先修基线，不解释为新方向无效。

# 3. 阶段 V0（续）：复用边界与统一输入

## V0.4 冻结候选任务与训练表示

V1 的两个开发任务采用 `bowl_on_plate` 与 `mug_on_plate`；V5 增加 `stack_bowls` 作为第三个任务族。若某任务无法提供有意义的障碍布局，只更换该任务并记录原因，不为了制造结果任意提高障碍难度。

第一版沿用 Point Bridge 已跑通的动作输出和控制器接口，冻结动作预测长度、实际执行长度与时间聚合方式。**暂不同时改成新的未来机器人点—逆运动学链路**；这是相对前期讨论的主动收窄，用于隔离视觉输入贡献。

建立持续任务点身份：操作物体和目标各保留固定语义槽位。可用首帧可见表面点加因果跟踪初始化。每帧重新做最远点采样得到的是无序点集，不能把“第 5 个点”当作跨帧同一实体。无序上下文点与持续任务点使用不同字段。

建议开发预算为每帧 64 个点：机器人点 9、任务点 16、上下文点 39。任务槽位按两类对象分配；无有效观测时保留 mask，不以零坐标冒充观测。若清洁条件出现明显容量不足，只允许在 V0 比较 64 与 128，再统一冻结一个预算。上游原配置另列为参考，不与预算匹配消融混同。

## V0.5 建立可见观测层

所有 P/V 等级输入从当前相机 RGB-D 构建。纯视觉遮挡必须同时影响颜色、深度和点提取；不能只遮图片，仍把完整对象真值点输入策略。

仿真真值放入独立监督目录，供遮挡位置误差、可见性标签和成功判断使用；策略数据读取器不得读取隐藏状态。保存 `observed / predicted / unknown` 状态、点身份、最后观测时刻、相机标定和数据时间戳。

| 旧资产 | 本项目处理 | 复用条件 |
|---|---|---|
| 旧环境安装经验 | 作为参考，不复制整个环境 | 与新底座依赖不冲突 |
| 旧场景/评测脚本 | 可定点移植 | 新动作接口、重置与成功定义正确 |
| 旧状态轨迹 | 条件性复用 | 完整状态和场景足以回放；重放成功 |
| 统计与配对评测思路 | 优先复用 | 同 seed、同场景正确配对，数值类型正确 |
| DataMIL、元梯度、Orbit、阶段代理 | 不迁移 | 与新方法无关 |
| 旧 checkpoint 与 Top-20 | 仅归档 | 不作为新策略或主结果 |

旧仓库公开版本将大型数据和 checkpoint 替换为占位文件，因此需要时只能从原实验机器读取真实资产，不可把占位文件当成下载完成的数据。[6]

**阶段交付：**`v0_handoff.yaml` 明确任务、动作协议、点预算、输入等级、数据根目录和下一阶段参数。缺真实资产时，只阻塞对应复用分支，不阻塞上游数据主路径。

# 4. 阶段 V1：验证两个问题，并建立四条件实验

**总体上要改进什么：**将“看不到任务点”与“看不到动作约束”分开，证明基线的具体失败原因，而不是先训练完整新方法再寻找解释。

## V1.1 建立四类场景

| 条件 | 视觉遮挡 | 动作约束上下文 | 要回答的问题 |
|---|---:|---:|---|
| E00 | 无额外遮挡 | 无新增障碍 | 正常能力是否足够 |
| E10 | 有 | 无新增障碍 | 点信息缺失是否导致失败 |
| E01 | 无额外遮挡 | 有障碍/边缘约束 | 仅任务点是否不足以决定可行动作 |
| E11 | 有 | 有 | 两种问题同时存在会怎样 |

“无上下文约束”指无新增的关键避障约束，不表示场景中没有桌面和支撑面。四条件由两个可独立控制的因素组成。

## V1.2 制作真正改变观测的遮挡

开发时设置三类干预：短时任务点被挡、机械臂自遮挡、再出现时易发生身份混淆。第一轮重点为目标已看见后再被遮挡，另将“开始就从未看见”作为困难测试，不能要求记忆恢复不存在的信息。

可用不参与碰撞的渲染遮挡物验证纯感知效应，但须明确它是诊断条件，RGB 与深度必须一致；V5 再使用真实几何遮挡物或真实物体遮挡。遮挡事件按预先冻结的时间表触发，不根据当前模型即将失败的时刻逐方法定制。

开发遮挡时长建议 0.25、0.5 秒；确认测试保留 1.0 秒及不同遮挡位置。若物体在隐藏期间被外力任意改变且无任何可见线索，该条件只用于测不确定性与边界，不设定必须成功的门槛。

## V1.3 构造需要上下文才能区分的布局

保持操作物体、目标和任务语言尽量相同，分别放置左侧/右侧挡板、调整开口或通道位置，使所需动作发生变化。障碍由新实验脚本添加，并明确标为自定义任务变体，不声称上游已提供。

每个物理新布局必须有可行示范。可从已有演示经适配再执行、脚本专家、运动规划或人工录制获得；**不能只修改障碍位置，却继续使用会穿过障碍的旧动作作为专家标签。**记录示范成功、非必要接触和控制约束。

对于 E01/E11，训练集也必须包含布局变化。只在测试突然加墙可以测分布偏移，但不能充分判断上下文学习方法本身。

# 5. 阶段 V1（续）：数据划分、对照与决策

## V1.4 冻结数据与基线矩阵

开发集每任务先使用约 100 条有效物理演示，覆盖正常和约束布局；每条可派生不超过两种遮挡观测。预算建议，不足时在 V1 结束前一次性调整。派生观测不计作新的独立物理演示。

先按 `source_episode_group_id` 和布局家族划分训练/验证/测试，再生成遮挡或相机变体。同一原轨迹的所有重渲染版本必须在同一划分。验证集只用于冻结参数，测试布局和遮挡模式不参与调参。

开发基线为：同底座稀疏任务点策略、同底座预算匹配全场景点策略、较高点预算全场景策略；图像策略延后到 V5，不在第一轮铺开全部论文复现。

物理动作、控制周期、训练演示和有效更新数保持一致。点数预算匹配组与大输入能力参照分开报告。

## V1.5 执行诊断并确定后续分支

两个任务、三个训练 seed、每 seed 每条件 50 个固定场景。每个 checkpoint 在四条件下评测；统计采用配对场景。只要训练配置和数据不变，之后重复使用 checkpoint，不为下一阶段重新跑相同基线。

同时做少量诊断替换：隐藏对象真值点上界、人工正确上下文上界。它们不计入主方法，只回答缺失信息是否是实际瓶颈。

**进入 V2：**遮挡造成可复现的下降，而且当前点/记忆处理仍有改善空间。遮挡点真值替换恢复性能，支持感知原因；完全不恢复则先看控制或示范质量。

**进入 V3：**可行布局中，输入约束上下文相较只保留任务点带来方向一致的帮助，或存在明确的任务点别名状态导致错误动作。若只改变物体位置已足以推断障碍，不用该布局宣称上下文必要。

开发中将 10 个百分点的下降作为值得优先研究的参考幅度，而不是机械停止阈值。效果小但置信区间很宽时标为证据不足；只补一次预先规定的额外评测，不无限提高难度或追加随机种子。

### 阶段交付与边界

交付 `scenario_registry.csv`、数据划分、基线矩阵、按条件成功率和失败视频。失败样例按固定场景 ID 或分层抽样取出，不只挑最差案例。

允许仅继续可见性或仅继续上下文分支，不要求两项都明显才能推进；也不因为一个方法没学会就认定整个方向错误。

# 6. 阶段 V2：任务点记忆与可信度

**总体上要改进什么：**让策略区分“当前看见的位置”和“历史推测的位置”，在短时遮挡期间保留有用信息，同时避免把过时记忆当成事实。

## V2.1 从最简单的记忆开始

为每个持续任务点保存：位置估计、可见状态、是否已初始化、距离最后可靠观测的时间及角色。机械臂本体点从当前传感器获得，不沿用视觉遮挡规则。

先实现两个无需新训练网络的参照：上一位置保持；保持位置并输入可见标记与记忆年龄。固定物体短时静止假设需明确；仅因夹爪关闭不能认定物体已经被抓住。

“随夹爪刚性传播”的版本只在可观测证据支持抓持时使用，并作为单独消融。如果无法可靠确认抓持，宁可增大位置不确定性，也不能读取模拟器真实接触标签决定测试时传播模式。

## V2.2 建立轻量因果点状态估计

候选状态可表示为

$$
b_{j,t}=(\mu_{j,t},\sigma_{j,t}^2,v_{j,t},\Delta t_{j,t},r_j,m_{j,t}).
$$

其中 $m$ 表示已初始化和有效性。第一版使用对角方差，避免复杂全协方差；输入仅含当前及历史观测、过去已执行动作和本体状态。不能使用未来图像、双向离线跟踪结果或专家未来动作。

先比较规则传播与小型时序网络，再决定是否保留学习模块。位置误差和不确定性监督可使用仿真标签，但只在训练损失中使用。全部方法保持相同历史窗口，开发起点建议 8 帧，并记录实际秒数。

## V2.3 重新可见时更新身份和状态

点重新出现后依据角色、外观描述与预测位置进行匹配。匹配不可靠时输出 `unknown` 或重新初始化，不把错误对象直接接到旧轨迹上。未出现过的点保持未知，不预测一个看似确定的物体位置。

输出置信度要验证覆盖率：例如名义 90% 位置区间实际覆盖多少真值。上下文模块未来使用的是经过校准的置信量，而不是任意跟踪器分数。

## V2.4 可见性模块对照实验

仅在 E00/E10、固定无新增障碍下比较：上一位置保持；保持＋mask/年龄；同历史窗口普通时序策略；候选可信点记忆。训练遮挡暴露与随机点丢弃增强对所有可比方法一致。

最后增加“历史点云累积”简单基线，防止把已有时序累积的收益误当成不确定性贡献。候选方法应至少超过简单 mask/年龄或同历史窗口基线中的较强者。

**主要指标：**遮挡成功率、正常成功率、不同遮挡时长曲线；辅助报告位置误差、身份切换、再出现后的误差恢复时间。记忆降低点误差但不提高执行结果时，不继续扩大网络。

**交付：**`belief_config.yaml`、分时长结果、校准曲线、可见性模块冻结版本；训练和推理均明确 O/P/V 输入等级。

# 7. 阶段 V3：固定预算的环境上下文

**总体上要改进什么：**在任务点清楚可见时，验证少量环境点能否描述真正限制动作的几何；先用明确规则，不立即训练复杂点选择网络。

## V3.1 定义上下文点池和排除项

从当前可见深度中取得非任务表面点，转换到机器人基座坐标。场景角色可以在 P 条件下由仿真分割提供，在 V 条件下由视觉前端提供。所有主对照共享同一候选点池。

未知深度不视为自由空间；看不到的障碍不能通过模型网格偷偷补全。可见性记忆若后续允许保留过去上下文，必须为各方法提供相同历史输入并计入预算。

预定义哪些接触是任务允许的：桌面支撑、物体与容器接触不能一律算碰撞。第一版重点评测夹爪与携带物体的非必要碰撞，不宣称整条机械臂安全。

## V3.2 三种静态选择与一个上界

同一上下文预算下比较：随机选点；空间均匀/最远点采样；夹爪—物体—目标局部区域裁剪。局部裁剪结合固定比例的全局覆盖点，避免近处点占满预算。

仅为诊断设置“正确约束点上界”，例如直接获得障碍边界；该上界可用仿真标签，但不能与真实视觉方法混报。第一版不手工为每个测试场景挑点。

## V3.3 训练与比较

保持任务点全部可见，主要使用 E00/E01。任务点身份、动作头、历史窗口和训练预算与 V2 冻结配置一致。为隔离上下文贡献，先关闭新增可信记忆模块，或统一使用同一简单可见性处理。

关键对照分成两类：任务点数量固定，只更换上下文选择规则；总点数固定，用任务对象更多点与环境上下文点作替换。前者验证选择策略，后者验证信息分配。

对于“全场景点”基线，分别报告预算匹配版本和上游较高点预算版本，不强行把高预算上界称为公平算力对照。

## V3.4 机制与选择

测量 E01 成功率、非必要碰撞率及最小间距，并展示同一任务点配置、不同障碍布局下的动作是否变化。任务成功是主指标，不能只靠距离障碍变大认定改进；绕得很远但超时同样是失败。

如果普通最远点采样已经达到候选效果，就冻结该简单方案；它仍可作为后续基线，但不足以支持复杂动态选择的创新主张。

**交付：**一个最强静态选择器、一个同预算全场景点参照、固定的数据与场景清单。V4 不再重新搜索全部静态半径。

# 8. 阶段 V4：动作与不确定性条件的动态上下文

**总体上要改进什么：**将“该保留什么历史”和“当前该看什么环境”联结起来，在不增加点总数的情况下，让上下文选择服务于下一段动作。

## V4.1 冻结粗动作预测器

用任务点、本体状态和冻结的记忆模块训练或复用粗策略，输出短期末端轨迹。第一轮冻结粗策略，再训练上下文精修模块，避免同时改变多个目标。

训练上下文选择时使用粗策略自身的预测，而不是专家未来轨迹。若担心粗策略在训练轨迹上过度拟合，可按整条轨迹做交叉生成预测；至少必须保证没有从目标未来动作直接选点。

精修使用与上游相同的动作头和表示。增加一个“同样两次前向、但上下文不动态”的容量/计算对照，避免把额外预测器的收益当成选点收益。

## V4.2 根据扫掠空间选择点

用粗轨迹及已知夹爪几何近似下一段动作扫掠范围，而不只画一条末端中心线。携带物体几何只能来自允许的观测估计或统一已知模型。仅覆盖夹爪时，碰撞结论也限定于夹爪。

上下文优先来自：预测运动区域附近、目标边缘附近、全局覆盖保底区域。只挑原始直线路径附近的点会遗漏绕行所需的信息，因此任何版本都保留固定的全局点份额。

## V4.3 将点不确定性用于预算内分配

若任务点被遮挡，用位置不确定性扩大候选空间范围，并在任务点预测区域、路径附近和目标附近之间重新分配点。**改变的是选哪些点，不是点总数。**

$$
K_R+K_T+K_C=K_{\mathrm{total}},\qquad
K_{\mathrm{path}}+K_{\mathrm{target}}+K_{\mathrm{global}}=K_C.
$$

开发起点可为上下文份额 50%/25%/25%，总数取整后保持精确一致；这只是预先冻结的工程默认值，不是理论最优结论。若输入点不足，使用有效性 mask，不复制同一点充数制造更高置信度。

不确定性过高时不能据此默认存在一条安全路径；模型只获得“缺信息”的标记。完全不可观测的变化仍作为能力边界报告。

## V4.4 形成联合输入并冻结主方法

完整流程为：因果任务点记忆 → 粗动作 → 预算内上下文选择 → 动作精修 → 执行 → 下一次观测。视觉前端、粗策略、点选择和精修均纳入推理时间。

只在验证集比较有限的 2–3 个窗口或分配参数。保留一个主配置和一个简单备选，进入 V5 后不得依据测试结果反复改方法。

# 9. 阶段 V4（续）：联合实验与推进规则

## V4.5 主消融矩阵

| 方法 | 可信任务点记忆 | 上下文 | 目的 |
|---|---:|---|---|
| M0 | 无新增模块，使用最强简单历史基线 | 最强静态选择 | 联合实验基线 |
| M1 | 有 | 同 M0 | 记忆的独立作用 |
| M2 | 同 M0 | 动作条件选择 | 动态上下文的独立作用 |
| M3 | 有 | 动作＋不确定性条件选择 | 完整方法 |
| M4 | 有 | 动作条件但忽略不确定性 | 验证两模块是否真正联动 |
| M5 | 同 M3 | 同样双前向但静态上下文 | 排除额外计算/容量解释 |

M0 不刻意使用弱的“零填补”版本。主矩阵均固定任务点和上下文总预算；无记忆方法不能少给历史帧，同一窗口下如何处理历史才是被比较的变量。

## V4.6 四条件与预算曲线

所有方法执行 E00/E10/E01/E11。主关注 E11 与正常条件的联合权衡；同时分别报告 E10、E01，避免主方法只解决其中一个因素。

预算曲线只在主配置冻结后做，例如总点数 32/64/128；每个预算各方法一致，角色配额规则在实验前固定。若 V0 冻结主预算为 128，曲线仍可包含较小预算，但不得用不同预算的最佳点分别比较。

额外做一个有限的点选择机制实验：打乱置信度或把路径条件换成固定直线，观察真实成功和碰撞变化。无需增加大量注意力可视化或与推进无关的诊断。

## V4.7 什么时候继续，什么时候收窄

开发参考目标：完整方法在困难条件较最强简单基线提高约 5 个百分点，同时正常条件下降不超过约 5 个百分点；这些是实用效果参考，不是仅凭一次均值即可宣布通过的门槛。

结合种子一致性、配对区间与延迟判断。如果只有 V2 或 V3 有效，就收窄论文；如果 M3 不优于 M4，不把不确定性分配包装成核心贡献；如果 M3 不优于 M5，不能宣称动态选点优越。

“V2 单独提升不足”不自动否定联合方法：只要预定 V4 实验显示明确互补作用，允许验证联合假设。不得重复旧研究中“必须单模块成功，否则组合正结果也作废”的决策方式。

**交付：**`method_freeze.yaml`、方法矩阵、完整实验成本、主/备选配置、支持与不支持的主张。结果不明确时标记 `inconclusive`，不要自动写成概念失败。

# 10. 阶段 V5：真实视觉前端与独立确认

**总体上要改进什么：**把可见真值点条件下的机制，放回真正会漏检、错配和深度不准的视觉链路，确认它不是只依靠仿真特权信息成立。

## V5.1 冻结一个可落地的视觉前端

输入采用单个固定 RGB-D 相机，或同一套固定双目；二者择一，不在第一轮同时比较所有深度网络。对真实硬件按实际传感器决定。可借用上游的分割和跟踪工具，但必须验证任务初始化、持续身份与点置信输出。[3–5]

初始角色可用冻结的语言提示、一次人工框/点击或视觉模型确定。选定后所有基线使用同样初始化成本；不能只给候选方法人工正确标注。单任务初版不训练语言模型。

对 Point Bridge 官方仿真视觉分割可靠性提示，不以读取隐蔽真值来掩盖问题。若自动语义分割尚不可靠，可先使用一次初始化加因果跟踪完成明确限定的“已知任务对象”实验，再作为下一项扩展自动初始化。

## V5.2 用匹配前端完成训练与评测

提前缓存训练集的因果视觉提取结果；不能用整段视频的后向修正去生成看似在线的点。缓存记录前端版本、相机标定和时间戳。

候选模型与可比基线在同样的 V 输入上训练或进行同预算适配，再评测。真值点训练后直接改用噪声视觉输入，仅作为迁移测试，不与匹配训练的主结果混淆。

训练时真值可用于监督，但推理时隐藏对象位置、未来动作、真实抓持关系、专家恢复轨迹均不进入模型。作用范围固定为观测到的刚性物体及短时遮挡。

## V5.3 三任务与未见条件测试

采用两个开发任务和一个未参与方法选择的任务族，每任务单独训练策略，避免把多任务学习引入为新变量。第三任务的算法配置沿用已冻结规则，只允许在公开训练/验证数据上确定必要的动作维度和归一化。

测试包含：新布局、未见遮挡位置/时长、少量不同物体实例、相机小幅位移。物理布局和相机位移分开报告；新的相机标定由允许的正常校准获得，不将其冒称无需标定的视角不变性。

新增图像策略与较高点预算全场景策略作为外部参照。若无法按相同数据与控制器复现某篇论文，不填入其论文数字与本结果直接比较；列明尚缺该参照。

# 11. 阶段 V5（续）：统计、时延与成功定义

## V5.4 确认性实验规模

正式主矩阵建议：4 个核心变体（M0–M3）× 3 个任务 × 5 个独立训练 seed，共 60 个策略运行。每个运行在四条件各 100 回合评测，共 24,000 回合。此为达到 V5 后的上限主计划，不在 V0 一次性启动。

M4/M5 和外部基线按需纳入两个代表任务，避免所有附加消融都铺满三任务。数据、模型、训练配置和输入前端完全一致的旧运行直接复用；配置改变时明确新 run，不覆盖旧结果。

每次评测独立重置环境、策略历史、点记忆与缓存。在线记忆不能携带前一个回合已经看过的物体位置。

## V5.5 指标层级

**主要结果：**任务成功率，按四条件及每个任务分别报告。主比较为完整方法与预先指定的最强简单基线，不在看过测试后重新指定最弱对手。

**辅助结果：**非必要碰撞率、超时率、重新可见后的恢复时间、点身份错误、不确定性覆盖率。未知或模拟器异常不悄悄当作普通失败，应单列异常数并按冻结规则处理。

**效率结果：**每帧输入点数、峰值显存、训练 GPU 小时、端到端推理 P50/P95、控制周期超时率。计时包括图像、深度、分割、跟踪、选点、两次策略前向和动作解码；离线预处理单列，不隐藏到总成本之外。

## V5.6 配对分析与判定

对每个训练 seed，先在对应场景上计算方法差异，再汇总。使用训练 seed 与场景 ID 的配对分层重采样，保持方法与条件间配对；跨任务先每任务平均，再宏平均，不把所有回合当成同一个大样本。

报告成功率差的百分点、区间和各 seed 结果，不把重采样中差值大于零的比例直接称为严格的显著性概率。即使区间包含零，也区分样本不足与明显无效。

对实时性采用两种口径：统一控制周期下的能力比较；实际端到端延迟下的系统比较。较慢方法不能通过暂停模拟器获得隐形优势。

**通过条件：**相较强简单基线，在未见困难条件存在可复现的实际收益，正常能力没有明显不可接受退化，且代价被完整披露。只提升点预测而不改善执行，或优势完全来自更多点/历史/计算，不支持原主张。

**交付：**独立测试结果、按条件曲线、冻结版本、失败边界和论文证据表；随后决定是否执行 V6。

# 12. 阶段 V6：可选实机验证与研究固化

**总体上要改进什么：**在有硬件时确认真实遮挡、深度噪声和计算延迟下的可用性；没有硬件时完成明确边界的仿真论文材料，不伪造实机或迁移结论。

## V6.1 实机条件与最小任务

沿用已具备的单机械臂、双指夹爪和固定 RGB-D/双目。Point Bridge 提供 FR3 部署文档，但用户是否具备该设备尚未知；不预设新采购，也不为匹配上游更换整套机器人。[3]

只做两个任务：一次遮挡主导的抓取放置；一次边缘/障碍主导的放置。安装满足现有实验室要求的急停、软限位和低速模式；先在无障碍条件校准坐标和动作，不安排危险碰撞来制造负样本。

## V6.2 实机对照与预算

优先比较预算匹配的任务点基线、最强静态记忆/上下文基线、完整方法。每方法、每任务、每条件先安排 20–30 回合，按场景分块随机顺序执行；人工重置、初始化和纠正次数都记录。正式所需样本量依据仿真和先导实机方差确定。

保持相同相机、动作速度、控制器、初始化方式与演示量。实机微调应每个方法使用同样的真实数据预算；零样本迁移与微调后结果分开。

## V6.3 复核能够写出的贡献

方法论文的主张优先集中为：持续点可信记忆、固定预算动作条件上下文选择、两者联合带来的闭环效果。相对坐标、现成分割模型和模仿学习动作头属于借用组件，不宣称重新提出。

如果动态版本未超过静态规则，就如实转为可见性或上下文单模块研究；如果只在理想分割条件有效，就限定为机制实验，不把它称为真实视觉鲁棒策略。

## V6.4 归档与发布

新仓库保留配置、数据划分、场景生成器、模型接口、评测脚本与必要失败样例。大数据、checkpoint 使用外部存储和清单管理；上游许可证与自己的新增代码明确分开。

文档记录：已确认结果、未通过的组件、未验证的扩展、运行硬件和复现入口。旧 `dm` 仓库只提供复用工具出处，不进入主实验代码依赖。

**完成标准：**他人能够按冻结配置重现实验表；每项论文主张对应实际实验；没有仅凭一个成功演示视频形成的结论。

# 13. 排期、算力与决策节奏

### 13.1 建议排期

以下是资源正常可用时的排期估计，不是对运行时长的承诺。核心阶段可按周推进；遇到数据资产问题，优先减少平台数量，而不是增加工程分支。

| 阶段 | 建议时间 | 计算与执行边界 |
|---|---|---|
| V0 | 3–5 个工作日 | 1 项任务、1 个开发 seed；旧资产复用检查不超过半天 |
| V1 | 1–2 周 | 2 任务、3 基线、3 seeds；四条件问题诊断 |
| V2 | 1–2 周 | 先 1 任务筛查，再 2 任务；不训练大视觉模型 |
| V3 | 1–2 周 | 3 种静态规则，复用相同数据和任务 |
| V4 | 2 周左右 | 冻结粗策略，有限参数，完整消融先在 1 任务筛查 |
| V5 | 2–3 周 | 真实视觉前端，3 任务与正式确认矩阵 |
| V6 | 2–3 周，可选 | 硬件可用才启动，按两任务最小对照执行 |

### 13.2 算力预算不要继承旧 DataMIL 规模

V0 在本机测量一次训练时长 $T_{\mathrm{train}}$、一次回合耗时 $T_{\mathrm{episode}}$ 和前端成本。阶段预算按实际任务分别估算：

$$
T_{\mathrm{stage}}\approx N_{\mathrm{runs}}T_{\mathrm{train}}+
N_{\mathrm{episodes}}T_{\mathrm{episode}}+T_{\mathrm{perception}}.
$$

官方文档给出的特定 GPU 速度不直接套用本机。[5] 单卡可顺序执行；前端特征可离线缓存，但必须保持因果性。CPU 只用于小规模接口检查，不预设能承担正式视觉模型训练。

### 13.3 三个关键决策点

**G1（V1 后）：**遮挡与上下文缺失是否确实限制现有策略？只继续有证据的分支。

**G2（V4 后）：**完整方法是否超过同预算、同历史和同计算的简单方法？只冻结有贡献的组件。

**G3（V5 后）：**优势是否在真实视觉链路和未见条件中保留？没有则限定研究范围，不以增加任务数量掩盖问题。

每个阶段可返回 `proceed`、`narrow_scope`、`inconclusive` 或 `blocked_interface`。接口错误不是科研负结果；单任务负结果也不是所有点策略不适用的证明。

### 14.3 最少的可靠性检查

仅安排：一个坐标重投影检查、一段动作闭环对齐、一次遮挡确实删除当前观测的检查、一次因果历史检查、一次成功计数检查。它们均直接影响实验含义。发现失败只修对应接口，不开启全面代码审计、依赖升级或代码风格重构。

### 15.2 相对前期讨论，执行上明确收窄的内容

一是上游采用 Point Bridge，不把其任务点变体称为 Point Policy 完整复现。二是保持现成动作头，不同时改控制表示。三是固定点总预算，动态改变内容而非偷偷增加点数。四是最早从 V0 就区分可见输入与隐藏真值，不能到实机阶段才补视觉可观测性。五是旧 MetaWorld 复用为可选项，不把旧 U0 或 DataMIL 数据恢复当作新研究前置条件。
